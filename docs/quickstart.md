# 5분 퀵스타트

논문 하나를 위키에 넣고, 그 위키에 질문해 보는 과정. 아래 출력은 실제로 실행한 결과다.

전제: 플러그인이 설치돼 있다 ([README의 설치](../README.md#설치)).

## 1. 위키 만들기

지식을 모을 디렉터리에서:

```
/xllmwiki:init
```

```
wiki root: /path/to/project
  wiki/{concept,entity,source,synthesis}/   pages, one directory per type
  raw/          verbatim sources
  .xllmwiki        marker
  wiki/index.md
  wiki/log.md
  wiki/SCHEMA.md
  wiki/.gitignore
```

`.xllmwiki`가 마커다. 이 파일 덕분에 프로젝트 어느 하위 디렉터리에서 명령을 실행해도
위키를 찾는다.

주제가 여럿이면 `/xllmwiki:init <도메인이름>`으로 도메인을 나눌 수 있다. 미리 나누지
말 것 — 주제가 실제로 갈라질 때 추가하면 된다.

## 2. 목적 정하기

`init`은 `purpose.md`를 만들지 않는다. 빈 템플릿을 남기면 채워지지 않은 채로 남아
판정 기준 역할을 못 하기 때문이다. 대신 스킬이 목표와 범위를 물어 함께 쓴다.

```markdown
# 목적

LLM 추론 최적화를 실무에 적용할 수 있을 만큼 이해하기.

## 범위

포함: 추론 지연·메모리, 서빙 아키텍처, 양자화.
제외: 학습 기법, 모델 아키텍처 연구 그 자체.

## 핵심 질문

- 컨텍스트 길이가 길어질 때 실제 병목은 어디인가
- 양자화가 품질을 얼마나 희생하는가
```

**이 파일이 이후 모든 판단의 기준이다.** 흡수에서 무엇을 생략할지, 질의에서 어떤
공백을 먼저 보고할지가 여기서 갈린다. 건너뛰어도 동작하지만, 그러면 생략 판정이 매번
즉흥적이 되고 위키가 목적 없이 커진다.

## 3. 소스 흡수하기

```
/xllmwiki:ingest https://arxiv.org/abs/1706.03762
```

URL, 로컬 파일, PDF, 붙여넣은 텍스트 모두 된다. 흡수는 이렇게 진행된다.

1. **원문을 `raw/`에 저장한다.** 저장하지 않은 소스는 나중에 재확인할 수 없는 주장이
   된다.
2. **위키가 이미 무엇을 아는지 확인한다.** 이 단계를 건너뛰면 중복 페이지가 생긴다.
3. **분석한다.** 엔티티·개념·주장·한계·기존 페이지와의 모순을 먼저 목록으로 만든다.
   읽으면서 바로 쓰면 3페이지째에 만든 것을 7페이지째에 또 만든다.
4. **소스 페이지를 먼저 쓴다.** `type: source` 하나. "이 논문이 뭐라고 했나"에 답하는
   유일한 곳이다.
5. **개념 페이지를 쓰고 인덱스를 갱신한다.**

결과는 이렇게 생긴다.

```
purpose.md
raw/vaswani-2017.md              # 원문 그대로
wiki/
  index.md                       # 지도
  log.md                         # 언제 무엇을 흡수했는지
  SCHEMA.md                      # 이 위키의 태그·규칙
  source/src-vaswani-2017.md     # 논문이 무엇을 주장했나
  concept/kv-cache.md            # KV 캐시란 무엇인가
```

소스 페이지와 개념 페이지가 나뉘는 게 핵심이다. "그 논문의 한계가 뭐였나"와 "KV 캐시란
무엇인가"는 다른 질문이고, 소스 페이지가 없으면 전자에 답할 곳이 없다.

## 4. 질문하기

```
/xllmwiki:query 긴 컨텍스트에서 메모리 병목이 어디인가
```

답변은 주장 단위로 인용되고, **위키에 있는 것과 추론한 것이 구분된다.** 위키가 답하지
못한 부분은 마지막에 따로 보고된다 — 그 목록이 다음에 무엇을 흡수할지 알려준다.

위키에 아무것도 없으면 그렇다고 말하고 멈춘다. 일반 지식으로 답하면서 위키가
뒷받침하는 것처럼 보이게 하지 않는다.

## 5. (선택) 그래프 컴파일

페이지가 늘어 읽는 비용이 부담되면:

```
/xllmwiki:graph
```

```
pages: 2  edges: 5 (typed: 1)  single file
  wiki/graph/graph.json  1.2 KB
```

그다음 본문을 읽지 않고 질의할 수 있다.

```
/xllmwiki:ask kv-cache에 무엇이 연결됐나
```

```
kv-cache -- 이전 토큰의 키·값 사영을 저장해, 새 토큰마다 전체 시퀀스를 다시 계산…
  -> sourced_from   raw/vaswani-2017.md        (raw source)
  -> mentions       src-vaswani-2017           순환·합성곱 없이 어텐션만으로 구성한…
  -> 근거함            src-vaswani-2017           순환·합성곱 없이 어텐션만으로 구성한…
```

**그래프는 선택이다.** 200페이지 아래에서는 `grep`으로 충분하다. 그래프가 값을 내는
건 질의로 답만 받을 때다 — 40페이지 실측에서 `graph.json` 전체(26,534자)는 페이지
본문(23,633자)보다 컸지만, 이웃 질의 1건은 893자였다.

## 6. 점검하기

```
/xllmwiki:lint
```

15가지를 검사한다. 인덱스에 없는 페이지, 인덱스가 가리키지 않는 관리 문서, 근거 없는
주장, 타입 불일치, 중복 slug, 낡은 그래프 등. 심각도로 묶어 보고하고, **고치기 전에
승인을 받는다** — 지식베이스를 조용히 자동 수리하면 무엇을 잃었는지 알 수 없다.

## 자주 걸리는 것

**페이지를 만들었는데 안 보인다** — `wiki/index.md`에 줄을 추가했는지 확인한다.
인덱스에 없는 페이지는 없는 페이지다.

**타입을 바꿨는데 컴파일이 `type mismatch`라고 한다** — `type:` frontmatter를 고쳤으면
파일도 해당 디렉터리로 **옮겨야** 한다. 복사하면 `duplicate slug`가 뜬다.

**멀티 도메인에서 명령이 도메인 목록만 보여주고 멈춘다** — 컨테이너 루트에서 실행한
것이다. 도메인 디렉터리로 들어가거나 `--domain <이름>`을 준다.

**흡수했는데 그래프 질의 결과가 낡았다** — 흡수·삭제 후에는 `/xllmwiki:graph`로 다시
컴파일한다. 낡은 그래프는 없는 것보다 나쁘다.
