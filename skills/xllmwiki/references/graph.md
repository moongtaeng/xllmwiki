# 그래프 (Graph)

마크다운 위에 올리는 **선택적 컴파일 인덱스**. 마크다운이 정본이고, `wiki/graph/`는
언제든 지우고 다시 만들 수 있는 파생물이다.

목적은 지식 표현이 아니라 **컨텍스트 절약**이다. 페이지를 읽으면 본문 전체가
컨텍스트에 들어오지만, 질의는 답만 반환한다.

## 측정치

40페이지 위키 실측 (문자 수):

| | 크기 | 비고 |
|---|---|---|
| 전체 페이지 본문 | 23,633 | 다 읽으면 이만큼 |
| `graph.json` 전체 | 26,534 | **본문보다 크다** |
| 라우팅 정보만 (`map`) | 3,916 | 83% 절감 |
| 이웃 질의 1건 | 893 | 96% 절감 |

250페이지에서는 질의 1건이 전체 본문의 **0.55%**였다.

**결론: 그래프를 통째로 로드하면 손해다.** 그래프는 메타데이터를 추가할 뿐 본문을
요약하지 않는다. 절약은 오직 질의로 답만 받을 때 나온다. 그래서 `graph.json`을
직접 읽지 말고 항상 `wiki_query.py`를 쓴다.

## 스크립트

표준 라이브러리만 쓴다. `uv`도, `pyyaml`도, 설치할 것도 없다.

```bash
python3 "<skill>/scripts/wiki_graph.py"      # 컴파일
python3 "<skill>/scripts/wiki_query.py" <명령>     # 질의
```

`SKILL.md`가 있는 스킬 디렉터리 기준 `scripts/` 아래에 있다.

### 컴파일

페이지를 읽어 [JSON Graph Format v2](https://jsongraphformat.info/)로 출력한다.
표준 포맷이므로 나중에 시각화 도구에 그대로 넣을 수 있다.

엣지 세 종류가 나온다.

- **typed** — `relations` 프론트매터에서. 인용문과 `status`를 지닌다.
- **`mentions`** — 본문 `[[링크]]`에서. 근거가 아니라 항해용이다.
- **`sourced_from`** — `sources[]`에서. 페이지와 소스를 잇는다.

흡수·삭제 후 다시 돌린다. 안 돌리면 그래프가 낡고, 낡은 그래프는 없는 것보다 나쁘다.

### 질의

| 명령 | 답하는 질문 |
|------|------------|
| `map` | 위키에 무엇이 있나 (본문 없이 전체 지도) |
| `neighbors <slug>` | 이 페이지에 무엇이 연결됐나 |
| `facts <slug>` | 이 페이지에 대해 근거 있는 관계가 무엇인가 |
| `path <a> <b>` | 두 페이지가 어떻게 이어지나 |
| `find <용어>` | slug·제목·요약·태그에서 검색 |
| `status disputed` | 논쟁 중인·대체된 관계 |
| `orphans` | 아무도 링크하지 않는 페이지, 끊긴 링크 |

`--json`으로 기계 판독 출력, `--wiki DIR`로 위치 지정.

질의는 한국어·중국어·일본어·러시아어 등 모든 문자를 지원한다. 유니코드 정규화(NFC)로
비교하므로 자모 조합 방식이 달라도 같게 찾는다.

## 샤딩

200페이지를 넘으면 컴파일이 자동으로 나눈다.

```
wiki/graph/
  index.json          # 라우터: 샤드 목록 + 각 샤드의 slug
  shards/<태그>.json   # 샤드별 노드 + 내부 엣지
  cross.json          # 샤드 경계를 넘는 엣지
```

샤딩 축은 첫 태그(없으면 `type`)다. 한글·CJK 태그도 파일명으로 그대로 쓴다.

질의는 이를 알아서 처리한다 — `neighbors`·`facts`는 해당 샤드와 `cross.json`만 읽고
(250페이지에서 8개 파일 → 3개), 나머지 명령은 전체를 훑는다. 다른 샤드에 있는 이웃은
`(in shard: X)`로 표시된다.

200페이지 미만에서는 샤딩하지 않는다. 파일 하나로 충분하고, 그 규모에서 샤딩은 마찰일
뿐이다. 페이지가 줄어 임계 아래로 내려가면 컴파일이 다시 단일 파일로 합친다.

## 버전 관리

`wiki/graph/`는 전부 파생물이다. `.gitignore`에 넣는 것이 기본이다.

PR에서 그래프 변화를 diff로 보고 싶다면 `index.json`만 추적할 수도 있다. `graph.json`
전체를 추적하면 페이지 하나 고칠 때마다 거대한 diff가 생긴다.

## 없어도 된다

그래프는 선택이다. 없으면 `grep`으로 충분하고, 200페이지 아래에서는 실제로 그렇다.
필요해지는 시점은 두 가지다.

- 위키가 커져서 `index.md`를 읽는 것만으로도 부담될 때
- 엔티티 간 관계를 반복해서 묻게 될 때 (누가 무엇을 만들었나, 무엇이 무엇에 의존하나)

그때까지는 컴파일하지 않아도 위키가 온전히 동작한다.
