# 삭제 (Delete)

소스나 페이지를 지우는 작업. 파일 하나를 지우는 것으로 끝나지 않는다 — 그 소스를
근거로 삼던 주장들과 그 페이지를 가리키던 링크들이 남아 위키를 조용히 망가뜨린다.

**항상 계획을 먼저 보여주고 승인을 받는다.** 지식베이스 삭제는 되돌리기 어렵고, 무엇이
딸려 나가는지 사용자가 예상하지 못하는 경우가 대부분이다.

## 소스를 지울 때

### 1. 영향 범위를 조사한다

```bash
# 페이지 파일 목록 — 타입 디렉터리 전체, 빈 디렉터리에도 조용하다
PAGES=$(find wiki -mindepth 2 -maxdepth 2 -name '*.md' -not -path '*/graph/*')
S=raw/<소스 slug>.md
grep -l "$S" $PAGES              # 이 소스를 인용하는 모든 페이지
grep -rn 'type: source' wiki --include='*.md' -r -l | xargs grep -l "$S"   # 소스 페이지 자체
```

각 페이지를 세 부류로 나눈다.

- **이 소스만 인용** (`sources`에 이 소스 하나) — 소스가 사라지면 근거가 전부
  사라진다. 삭제 후보다.
- **여러 소스 중 하나** — 페이지는 남기고, 이 소스에서 온 주장과 각주만 제거한다.
  다른 소스가 뒷받침하는 내용은 그대로 둔다.
- **소스 페이지** (`type: source`) — 이 소스 전용이므로 함께 삭제한다.

### 2. 계획을 제시한다

무엇을 삭제하고, 무엇을 편집하고, 무엇이 남는지 파일별로 보여준다. 특히 **여러 소스를
인용하던 페이지에서 무엇이 빠지는지**를 명시한다 — 페이지가 남는다고 해서 내용이
온전한 것은 아니다.

주장을 제거하면 그 페이지가 껍데기만 남는 경우도 있다. 그때는 삭제 후보로 다시 분류해
사용자에게 판단을 넘긴다.

### 3. 실행한다

승인받은 뒤 순서대로.

1. 해당 페이지 삭제
2. 남는 페이지에서 이 소스에서 온 주장·각주·`sources` 항목 제거, `updated` 갱신
3. `raw/<소스 slug>.md` 삭제
4. 끊긴 링크 정리 (아래)
5. `wiki/index.md`에서 삭제된 페이지의 줄 제거
6. `wiki/log.md`에 삭제 기록 append — 무엇을 왜 지웠는지
7. `wiki/graph/`가 있으면 재컴파일 (`python3 "<skill>/scripts/wiki_graph.py"`)

삭제 전에 영향 범위를 그래프로 조사할 수도 있다. 파일을 열지 않고 무엇이 딸려 있는지
보여준다.

```bash
python3 "<skill>/scripts/wiki_query.py" neighbors <slug>
python3 "<skill>/scripts/wiki_query.py" facts <slug>
```

## 페이지를 지울 때

소스는 남기고 페이지만 지우는 경우(중복 병합, 범위 이탈).

```bash
grep -rn '\[\[<slug>\]\]' wiki/           # 이 페이지를 가리키는 모든 곳
```

가리키는 곳이 있으면 그냥 지우지 않는다. 셋 중 하나를 택한다.

- **병합** — 내용을 다른 페이지로 옮기고, 링크를 그 페이지로 재지정한다. 중복
  정리에서는 이것이 기본값이다.
- **재지정** — 내용은 버리되 링크는 더 적절한 페이지로 돌린다.
- **링크 제거** — 링크를 가리키는 문장이 링크 없이도 성립할 때만.

내용을 버릴 때는 사용자에게 그 내용을 보여준 뒤 승인을 받는다.

## 끊긴 링크 정리

삭제로 생긴 끊긴 링크는 lint가 보고하는 끊긴 링크와 다르다. lint의 것은 "아직 안 쓴
페이지"라는 메모지만, 삭제로 생긴 것은 **있었던 것이 사라졌다**는 흔적이다.

`## See also` 목록에 있던 항목이면 줄을 제거한다. 본문 문장 안에 있던 링크면 대괄호만
벗기고 텍스트를 남긴다 — 문장이 무엇을 말하려 했는지는 보존할 가치가 있다.

## 하지 말아야 할 것

**모순 정리를 삭제로 하지 말 것.** 두 페이지가 어긋날 때 하나를 지우는 것은 판단을
지우는 것이다. `ingest.md`의 모순 처리를 따라 양쪽을 병기한다.

**`raw/`를 정리 목적으로 비우지 말 것.** 용량이 아까워도, 인용을 재확인할 수 없게
되면 위키 전체의 신뢰가 무너진다. 정말 지워야 하면 그 소스를 인용하는 모든 페이지를
위 절차로 함께 처리한다.
